No. 1 · The Registry · Models 1.0

No decorator. No envelope. Just the data.

A template's model declares exactly one concrete TemplateData subtype, and that type is the template: the grammar renders it and logic reads it. A stateful template declares one StateData subtype the same way.

Shape
concept CopyrightLicenseData extends TemplateData { … }
concept CopyrightLicenseState extends StateData { … }
TemplateData
The root is found by its parent type, so @template goes, and so does the Contract envelope. Where the models hold several TemplateData types, package.json's accordproject.templateModel names the root.
StateData
State has the same shape as data, and is found the same way. The runtime wraps it with identity and a revision.
PartyRef
A portable reference to a party. It replaces eight loose strings per licence, and a relationship that logic could never resolve.
PreciseAmount
An integer unscaledValue plus a unit with a scale: $100.00 is "10000" at scale 2, and arithmetic is exact BigInt.
@1.0.0
Every base namespace is versioned. A published version never changes, so a template's types are fixed at compile time.

Template authors change

  • Remove @template and the Contract or Clause supertype.
  • Extend TemplateData; add one StateData subtype if the template keeps state.
  • Use PreciseAmount for money and PartyRef for parties.
  • Import Request and Response from runtime@1.0.0.

What you get

  • The grammar roots at the data: {{effectiveDate}}, with no {{#with data}} wrapper.
  • Exact money, at any magnitude.
  • No envelope, so no doubt about which copy of the data is the real one.

No. 2 · The Conveyancer's · Documents and clauses

An agreement is one tree.

A document is the root template instance. Each clause composed into it is a child instance, with its own template and its own data. Inline clauses stay where they are, inside their template's data.

Shape
AgreementDocument { documentId, template, data, clauses: map<path, Clause> }
Clause { template, clauseId, data, clauses?, clauseHash? }
documentId
The document's instance id.
clauses key
Where the clause sits in its parent's grammar, e.g. latePayment.
clauseId
The clause's stable instance id, e.g. licence/late-payment.
data
The clause's own TemplateData. The parent's model declares nothing about it.

Template authors change

  • Nothing, for inline clauses.
  • A reusable clause becomes its own archive, with its own model, grammar and logic, and is composed in.

What you get

  • One structure for the whole hierarchy. No parallel maps of data and clause state to keep in step.
  • A clause written once and composed into any document.

No. 3 · The Strongroom · Agreement state

One index of state, keyed by instance.

The agreement's state is one flat index from instance id to that instance's own StateData. In models#205 it replaces models#200's data and clauseStates.

Shape
AgreementState { stateId, agreement, revision, effectiveAt, states: map<instanceId, StateData> }
states
One entry per stateful instance. A stateless instance has none.
revision
Goes up by one for each request the agreement commits.
effectiveAt
The committed request's timestamp.

Template authors change

  • Nothing. Logic sees only its own state, at its own type.

What you get

  • Stateless templates cost nothing.
  • Keys are stable ids, so the tree can change shape without migrating state.
  • One revision for the whole agreement.

No. 4 · The Clerks' Windows · Logic

One handler per request. No switch.

Logic registers one handler for each request type it handles. The engine dispatches on the request's type, and each handler's signature declares what callers get back.

Shape
defineLogic<Self>()
  .init(self => …)
  .on(RequestType, async (request, self): Promise<Response> => …)
.init(self)
Seeds state and emits the first events.
.on(Type, …)
Registers a handler. request is typed by the request type.
Promise<…>
The declared response is the template's API.
ApiOf<…>
Collects the handlers into what a composing template can trigger.

Template authors change

  • Replace class … extends TemplateLogic and its switch with defineLogic(), from @accordproject/template-engine/logic.
  • Handlers take (request, self) instead of (data, request, state).

What you get

  • No casts. A switch on $class never narrowed the request's type.
  • A request nothing handles is rejected before any logic runs.
  • A subtype falls back to its nearest supertype's handler.

No. 5 · The Library · self

Read the whole agreement. Write only your own.

self is the template's own node in the agreement tree. It reads its own data and state, and reaches every other instance by walking the tree.

Shape
self.data · self.state · self.parent · self.clauses
self.document.agreement.documents · agreement.resolve(reference)
InstanceReadWrite
Itselfdata, statesetState, emit
Its own composed clausesdata, stateonly by trigger
Parent, cousins, other documentsdata, statenone

Template authors change

  • Read parties, documents and other clauses through self instead of passing them in.

What you get

  • Logic reads parent documents and cousin clauses.
  • Writing anywhere else fails to compile, and the views are frozen at runtime.

No. 6 · The Chancery · Transactions

Commit everything, or nothing.

Handlers write only through self. The engine buffers every write and commits the request as one revision, or nothing if the handler throws. Each clause call runs in a nested transaction of its own.

Buffered
A handler sees its own writes straight away. Nobody else does until commit.
Nested
A clause's writes merge into its parent's when it returns, and are discarded if it throws. A parent that catches the error loses only the clause's writes.
Deterministic
Timestamps come from the request, never the clock, so a replay reproduces every outcome.

Template authors change

  • Call setState and emit instead of returning state and events.
  • Take time from request.$timestamp, not new Date().

What you get

  • A document and its clauses stay consistent without any code to keep them so.
  • Replayable, auditable logic.
template-engine#187 · src/agreement/execute.ts test/AgreementLogic.test.ts

Paying in full, as one revision

  1. The request arrives. PaymentReceived for the outstanding 100.00 USD, at revision 1.
  2. The licence records it. licence.setState(…) sets amountPaid to the full fee.
  3. It fulfils the obligation. licence.emit(…) records the move from DUE to FULFILLED.
  4. It discharges the clause. latePayment.trigger(PaymentSettled…) runs in a nested transaction and sets discharged.
  5. The engine commits revision 2. Both states and the event commit together. Had anything thrown, revision 1 would stand untouched.

No. 7 · The Seal Office · Type factories

Every value, sealed by its type.

Every value is made with its type's factory, generated from the models. Logic never writes a $class by hand.

Shape
PayOut.create({ … }) · LicensedWorkSchedule.is(data) · PaymentObligation.ref(id)
.create()
Fills in $class, and $identifier for an identified type. Every required field must be given.
.is()
Checks a value's type and narrows it.
.ref()
Makes a relationship to an identified instance.
Request types
Also the keys handlers register under.
types.ts
Generated into logic/generated/ by template-engine-codegen: one conceptType or identifiedType factory per concrete type. The engine supplies the same factories at runtime.

Template authors change

  • Replace object literals with factories, and delete namespace string constants.

What you get

  • A mistyped or hand-written $class doesn't compile.
  • Generated by npm run compile: 45 factories for the licence.

No. 8 · The Recorder · Obligations

State records facts. The registry owns the status.

The licence fee is a PaymentObligation that moves from PENDING to DUE to FULFILLED. State keeps only facts, the amount paid and the due date. Logic derives the status and announces each change as an event.

Shape
ObligationIssued { obligation }
ObligationTransition { obligation: ref, fromStatus, toStatus, effectiveAt, revision }
Issued
Emitted by init. Added by models#205.
Transition
Carries an accurate fromStatus and revision, so the registry can check each one.
Reference
An AgreementReference naming the agreement, document and clause path. Its documentId is new in models#205.

Template authors change

  • Emit obligation events instead of storing a status.

What you get

  • No stored status that a registry could disagree with.
  • Obligation ids unique across agreements, such as licence-001/licence/paymentTerms.

No. 9 · The Moot · Testing

Rehearse every clause before it's argued.

Unit tests get a self that runs on the engine's own transaction code and records what the engine would commit. Composed clauses are replaced by typed stand-ins.

testInstance
A self for one template, with optional cousin documents, validated against the models. From @accordproject/template-engine/testing, like stubClause.
stubClause
A stand-in clause, typed by the clause's API, which records the requests it gets.
types.check.ts
Compile-time checks of the API, run with tsc.

Template authors change

  • Drop the global mocks of TemplateLogic.

What you get

  • Tests that match the engine's behaviour exactly.
  • A stubbed response of the wrong type doesn't compile.

No. 10 · The Porters' Lodge · Deployment

Run an agreement as a stateless function.

AgreementProcessor's entry points take JSON and return JSON, and run an agreement over several templates. One invocation loads the state, executes, and commits with a conditional write on the revision.

Shape
initialise(agreement, documents, effectiveAt)
  → { state@0, events }
execute({ agreement, documents, state@N }, documentId, request)
  → { result, events, state@N+1 }

Template authors change

  • Nothing. Legacy TemplateLogic templates run unchanged.

What you get

  • Serverless hosting with no state held between calls.
  • Safe retries, because logic is deterministic.
  • The agreement as the unit of deployment: composed clauses run in the same invocation as their parent.
  • Each template still runs alone: TemplateArchiveProcessor's init and trigger run it as the one document of an agreement.
template-engine#187 · src/AgreementProcessor.ts

One invocation

  1. Load the agreement, its documents and the state at revision N.
  2. Execute the request in memory.
  3. Commit state N+1 only if the store still holds revision N, and write the events to an outbox in the same write.
  4. Retry from the winning state if another request committed first.
  5. Return the stored result if the same request is delivered again.

For template authors

The Checklist

In the order to do them, for each template.

  1. Import the @1.0.0 base namespaces, and Request and Response from runtime@1.0.0.
  2. Remove @template; make the root extend TemplateData, and add one StateData subtype if the template keeps state. If the models hold several TemplateData types, name the root in package.json's accordproject.templateModel.
  3. Use PreciseAmount for money and PartyRef for parties.
  4. Optionally, move a reusable clause into its own archive and compose it in.
  5. Replace the TemplateLogic class and its switch with defineLogic().init().on() from @accordproject/template-engine/logic.
  6. Make every value with a factory generated by npm run compile, and delete hand-written $class strings.
  7. Take timestamps from the request or the data, never the clock.
  8. Emit obligation events, and keep only facts in state.
  9. Test with testInstance and stubClause from @accordproject/template-engine/testing.
